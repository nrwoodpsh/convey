# 2차 개발 통합 시나리오 — 운영자 관점 (관리 화면 순서)

> **무엇을**: 브라우저에서 관리 화면(대시보드)을 **실제 조작 순서대로** 밟으며, 2차에서 만든 기능이
> 그 자리에서 동작하는지 확인한다. (curl·docker 기반 기술 스모크는 맨 아래 부록 / `scripts/smoke-phase2.sh`.)
> **전제**: `docker compose up -d` 후 브라우저로 **http://localhost:8091** 열기.
> **미완(외부키)**: 실 YouTube 업로드·실 Supabase 로그인은 2차 점검 후 — 여기선 "발행 승인→상태"까지.

## 화면 한눈 지도

```
┌─ 상단 지표 스트립 ─ 그래프 노드·관계 · 오늘 기사 · 오늘 이슈 · 완성 쇼츠
├─ [오늘자 기사]  기사 선택 → 제작 마법사(5스텝)
├─ [생성쇼츠]     완성본 카드 → 미리보기 · 근거 · 발행
└─ [설정]         종목 · 키워드 · 소스 · 기간 · 시나리오 템플릿 · 배경 자산
```

---

## 시나리오 A — 운영 설정을 잡는다  ([설정] 탭)

> 수집·선별·제작이 이 설정을 따른다. content가 admin API로 중계(Database per Service).

| 순서 | 화면에서 할 일 | 기대 결과 | 동작 기능 |
|:--|:--|:--|:--|
| A1 | [설정] → **종목**: 검색창에 종목명/코드, 체크(ON/OFF) | 토스트 "OFF/ON", 목록 즉시 반영. 체크된 종목만 수집·이슈 대상 | ㉝ P1·P4 |
| A2 | **키워드**: 입력 후 [추가], 항목 [삭제]·토글 | 키워드가 수집 검색어에 추가/제거 | ㉝ P1·P3 |
| A3 | **소스**: naver·rss·dart 토글 | 끈 소스는 수집 안 함 | ㉝ P3 |
| A4 | **기간**: 1주/1개월/3개월 선택 | 수집 검색 기간 변경 | ㉝ P3 |
| A5 | **시나리오 템플릿**: 노브 편집(사실 수·관계 수·거시·마무리·훅 톤), [저장]·[추가]·[삭제] | 대본 형식이 admin_db에 저장(제작 마법사 스텝2에 나타남) | ㊳ |
| A6 | **배경 자산**: 이름·태그(예 `자동차`)·경로(`/data/media/...`)·종류 [등록] | 종목 섹터/이름 태그로 영상 배경 매칭에 사용 | ㊴ P1 |

**확인 포인트**: 아무 값이나 바꾼 뒤 새로고침 → 값이 유지되면 admin_db 왕복 OK. (설정 폼 CRUD는 P2 프런트, 백엔드 프록시는 P1.)

---

## 시나리오 B — 기사에서 쇼츠를 만든다  ([오늘자 기사] 탭, 5스텝 마법사)

> 알파① 근거·알파③ 정확 렌더가 이 흐름에서 눈에 보인다.

| 스텝 | 화면에서 할 일 | 기대 결과 | 동작 기능 |
|:--|:--|:--|:--|
| B1 · 기사 | 오늘자 수집 기사 목록에서 **종목 태깅된** 기사 [진행 ▶] | 미태깅 기사는 [진행 ✕](제작 불가). 태깅 종목명 표시 | ㉜ 태깅 · 수집 |
| B2 · 템플릿 | 시나리오 템플릿 칩 선택(속보/분석/스토리 = A5에서 만든 것) → [시나리오 생성 ▶] | 선택 템플릿의 노브로 대본 생성 | ㊳ |
| B3 · 시나리오 | 생성된 대본 표시 + **근거 패널** 자동 노출 | 대본 아래 **관계(그래프)·출처 URL·수치**가 보임(무출처 0) | ㊵ AC3 · 알파① |
| B4 · 수정→배경 | 문장 수정 [저장], [배경 선택 →] → 배경 모드 | 대본 편집 저장. 배경: 라이브러리(A6 태그 매칭)→생성→Pexels→로컬 | ㊴ |
| B5 · 생성 | [승인 → 쇼츠 생성 ▶] → 미리보기 | 잠시 후 완성 mp4 재생. 차트·수치 정확, **가독성 패널**(텍스트 뒤 어두운 밴드) | 알파③ · ㊴ AC4 |

**확인 포인트**: B3의 근거 패널에 출처 URL이 실제로 뜨는가(신뢰 가시화). B5 영상의 종목명 배경이 섹터와 맞는가.

## 시나리오 C — 완성본을 발행한다  ([생성쇼츠] 탭)

> 자동 발행 금지 — **사람이 버튼을 눌러야만** 발행. 트리거는 트랜잭션 아웃박스로.

| 순서 | 화면에서 할 일 | 기대 결과 | 동작 기능 |
|:--|:--|:--|:--|
| C1 | [생성쇼츠] 탭 → 완성본 카드 클릭 | 상단 미리보기 재생 + 시나리오 + **근거** | ㊵ |
| C2 | 미리보기 하단 **[▶ YouTube 발행 (승인)]** 클릭 | 토스트 "발행 승인됨". job이 approved로 | ㊶ C1 |
| C3 | (내부) 승인 → **아웃박스 INSERT(같은 트랜잭션)** → Debezium → publishing 소비 | 앱이 크래시해도 커밋된 이벤트는 발행됨(유실 0) | ㊱ P3 |
| C4 | 발행 상태 표시 | **현재: "발행 실패 · OAuth 자격증명 없음"** — 코드는 다 돎, 실 업로드만 refresh_token 대기 | ㊶(미완) |

**확인 포인트**: C2 후 `content_db.outbox`에 행이 생기고(같은 트랜잭션), 발행 상태가 뜨면 체인 전체 작동. 실 업로드는 [[pending-youtube-supabase]].

## 시나리오 D — 파이프라인을 관측한다  (지표 + 외부 콘솔)

| 순서 | 화면에서 볼 것 | 기대 결과 | 동작 기능 |
|:--|:--|:--|:--|
| D1 | 대시보드 **상단 지표 스트립** | 그래프 노드·관계 · 오늘 기사 · 오늘 이슈 · 완성 쇼츠 카운트 | ㊵ AC4 |
| D2 | **kafka-ui** http://localhost:8090 | 토픽 메시지가 **Avro 봉투**, 스키마 조회 | ㊱ P1·P2 |
| D3 | **Grafana** http://localhost:3000 | consumer_lag · throughput · **dlq_rate** 그래프 | ㊱ P5 |
| D4 | **Schema Registry** http://localhost:8085/subjects | 등록된 Avro subject 목록 | ㊱ P2 |

## 배경 자동 흐름 (화면 밖에서 돌아 지표로 반영)

운영자가 조작하지 않아도 백그라운드로 도는 것 — 결과는 D1 지표로 확인.

```
news·market feed ─(Kafka 봉투·Avro)→ research(개방형 NER → Neo4j 그래프)
                                          │
                                          ├→ issue-detector(관심목록 게이팅 → 이슈 선별)
                                          └→ 그래프 노드·관계 증가(D1 지표)
   실패 메시지는 재시도 후 *.dlq (P4) · 발행은 아웃박스→Debezium (P3)
```
관련: 수집·㉟ 온톨로지(노드9·엣지12) · ㊲ 이슈 dedup · ㊱ P1~P5.
